# Исправление проблемы с изображениями в Production

## Проблема
После деплоя изображения не отображаются нигде. Это происходит потому, что в production окружениях (например, Vercel) файловая система доступна только для чтения, и файлы не сохраняются между деплоями.

## Решение

### Вариант 1: Использовать внешнее хранилище (РЕКОМЕНДУЕТСЯ)

#### Cloudinary (бесплатный план доступен)
1. Зарегистрируйтесь на [Cloudinary](https://cloudinary.com/)
2. Получите API ключи
3. Установите пакет: `npm install cloudinary`
4. Обновите `app/api/ads/images/route.ts` для загрузки в Cloudinary
5. Обновите `app/api/user/avatar/route.ts` для загрузки в Cloudinary
6. Добавьте переменную окружения `NEXT_PUBLIC_IMAGE_BASE_URL` с URL вашего Cloudinary аккаунта

#### AWS S3
1. Создайте S3 bucket
2. Настройте CORS
3. Установите `@aws-sdk/client-s3`
4. Обновите API endpoints для загрузки в S3

#### Vercel Blob Storage
1. Установите `@vercel/blob`
2. Обновите API endpoints для использования Vercel Blob

### Вариант 2: Временное решение (для тестирования)

Если изображения уже загружены в production и сохранены в базе данных, убедитесь что:

1. Пути к изображениям правильные (должны начинаться с `/uploads/`)
2. Файлы действительно существуют в `public/uploads/` после деплоя
3. Next.js правильно обслуживает статические файлы из `public/`

### Вариант 3: Использовать базовый URL для изображений

Если изображения хранятся на внешнем сервере или CDN:

1. Добавьте переменную окружения `NEXT_PUBLIC_IMAGE_BASE_URL` в настройках Vercel
2. Установите значение, например: `https://your-cdn.com` или `https://your-cloudinary-url.cloudinary.com`
3. Функция `getImageUrl` автоматически будет использовать этот базовый URL для путей, начинающихся с `/uploads`

## Текущее состояние

Функция `getImageUrl` в `lib/utils.ts` обновлена для:
- Правильной нормализации путей
- Поддержки внешних базовых URL через `NEXT_PUBLIC_IMAGE_BASE_URL`
- Обработки абсолютных и относительных путей

## Следующие шаги

1. **Немедленно**: Проверьте, что изображения действительно загружаются в production
2. **Краткосрочно**: Настройте внешнее хранилище (Cloudinary рекомендуется)
3. **Долгосрочно**: Мигрируйте все существующие изображения на внешнее хранилище

## Проверка

После настройки внешнего хранилища:
1. Загрузите новое изображение через форму создания объявления
2. Проверьте, что оно отображается на странице объявления
3. Проверьте, что оно отображается в списке объявлений
4. Проверьте, что оно отображается в featured секции на главной странице
