# ПРАВИЛЬНАЯ ВАЛИДАЦИЯ ДЛЯ CHATS И MESSAGES

## Проблема
Непрочитанные сообщения не обновляются из-за строгой валидации MongoDB, которая блокирует обновление поля `read`.

## Решение

### 1. Используйте validationLevel: "moderate"
Это позволяет обновлять существующие документы без строгой проверки.

### 2. Выполните скрипт настройки

Скопируйте и выполните содержимое файла `mongodb-setup-chats-messages-fixed.js` в MongoDB Shell:

```bash
mongosh
use auen
# Вставьте содержимое mongodb-setup-chats-messages-fixed.js
```

Или через MongoDB Compass:
1. Откройте базу данных `auen`
2. Выберите коллекцию `chats` или `messages`
3. Перейдите в "Validation"
4. Вставьте соответствующую валидацию из JSON файлов

## Валидация для CHATS

**Файл:** `mongodb-chats-validation-fixed.json`

**Особенности:**
- `validationLevel: "moderate"` - позволяет обновлять существующие документы
- `additionalProperties: true` - разрешает дополнительные поля
- Поле `read` НЕ требуется (его нет в chats)

## Валидация для MESSAGES

**Файл:** `mongodb-messages-validation-fixed.json`

**Особенности:**
- `validationLevel: "moderate"` - позволяет обновлять поле `read` в существующих сообщениях
- `additionalProperties: true` - разрешает дополнительные поля
- Поле `read` может быть `bool` или `null`

## Важно!

1. **validationLevel: "moderate"** - это ключевой момент! Он позволяет обновлять существующие документы без строгой проверки всех полей.

2. Если валидация все еще блокирует обновления:
   - Временно установите `validationLevel: "off"`
   - Или используйте `bypassDocumentValidation: true` в коде (уже реализовано)

3. После применения валидации перезапустите приложение.

## Проверка работы

После применения валидации проверьте:
1. Откройте чат
2. Проверьте консоль сервера - должны быть логи о пометке сообщений
3. Проверьте консоль браузера - счетчик должен обновиться
4. Обновите страницу - счетчик должен остаться 0
